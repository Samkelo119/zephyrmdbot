# Vercel pairing console

Vercel serves the static pairing page; it cannot host the persistent Baileys/WhatsApp connection. Pairing codes are generated by the always-on backend.

1. Deploy this repo to Railway as the bot backend, generate a public domain, and attach persistent storage for `auth_info/` and `data/` before pairing.
2. In Vercel → Project → Settings → Environment Variables, set `BACKEND_URL` to the Railway public URL (for example `https://your-service.up.railway.app`). Do not include `/api/pair` in the value. Add it for Production and Preview if both deployments need pairing.
3. Redeploy Vercel so its build injects that backend URL into the pairing page.
4. Open the Vercel deployment, enter the WhatsApp number and session name, and generate the code. If pairing fails, the page now displays the backend's error response.
5. Keep the Railway service running and persistent. A Vercel deployment by itself cannot produce a code or keep a WhatsApp session online.

`BACKEND_URL` currently defaults to the existing Render backend for backward compatibility. Set it explicitly to your running Railway URL to avoid generating a code against an old or sleeping backend.
